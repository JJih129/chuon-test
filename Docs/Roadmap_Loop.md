# 개발 루프 운영 문서 (프로젝트 추온)

매 반복은 **제안 → 구현 → 검증 → 다음 제안** 순서로 돈다. 반복이 끝나면 이 문서의 백로그와 출시 게이트를 갱신하고, 남은 최우선 항목으로 다음 반복을 시작한다. 계획된 항목이 끝나도 루프는 멈추지 않는다. 출시 게이트를 통과하면 **폴리싱 단계**로 넘어가 계속 다듬는다.

## 반복 규칙
1. 반복 시작 전에 작업 트리를 스크래치 백업한다.
1-1. **큰 작업(반복)이 끝나면 검증 통과 후 `JIHUN_ing` 브랜치에 주제별로 커밋한다**(설정·아트/레벨·코드·문서 등). 푸시는 사용자가 요청할 때만 한다. 커밋 메시지에 반복 번호와 검증 결과(컴파일·콘솔·빌드)를 요약한다.
2. 에디터·플레이 모드는 한 작업자만 쓴다. 코드만 수정하는 작업은 파일 소유권을 나눠 병렬로 돌린다.
3. 검증은 필수다. 컴파일 에러 0, 콘솔 에러 0, QA 봇 수치, 스크린샷, 개발 빌드(전체 흐름 스모크 + 보스 봇 실행) 결과를 남긴다.
4. 엄격 리뷰: 매 반복마다 모든 분야(게임플레이, 레벨, 비주얼, UI/UX, 오디오, 접근성·옵션, 성능, 안정성, 코드 품질, 출시 준비)에서 근거와 함께 다음 5가지를 뽑는다.
5. 기획 문서(Docs/Story_Reference.md, Docs/Planning_Review.md)와 상충하면 표시하고, 사용자 결정이 필요한 것만 묻는다.
